## Рефакторинг

Из отложенного после v1 (делать **по касанию фичи**, не hygiene ради SOLID).

| ID | Когда трогать | Что | Не делать «просто так» |
|----|---------------|-----|-------------------------|
| R1 | Следующая крупная UX-правка Home | Вынести letter window / n-gram rail из `_HomeScreenState` в обычный контроллер (без BLoC/Riverpod) | Полный rewrite Home «для красоты» |
| R2 | Новая ось поиска / фильтров (напр. RU+tags) | Узкий split search-методов repo или общий `run(query, filters)`; **не** Strategy/SearchBackend заранее | Паттерн Strategy для KRL/RU «на вырост» |
| R3 | Второй backend или тяжёлый widget-тест Home | Abstract `IDictionaryRepository` / DI | Интерфейсы над одним sqlite |
| R4 | Рост SQL/поиска + реальная новая ось | Sibling-классы / private helpers вокруг `DictionaryRepository` | Преждевременная нарезка «толстого» repo |
| R5 | Касание drawer / update UI (в т.ч. F1) | Вынести `_UpdateDbPane` в отдельный файл | — |
| R6 | Второй UI-потребитель preview | `formatPreview` рядом с `article_format` | Перенос `previewLine` без нужды |

**Сознательно раздельно:** `orthography` ≠ `prepareKrlIlikeQuery` (разные порты Django); sheet ≠ route для статьи.
